# Data Catalog

Every Asgard data source — what it is, where it lives, where it goes in the archive, and the policy that governs it. The machine-readable version is `tenants/<tenant_id>/_meta/catalog.json` per tenant, generated by the `tyr-archive` daemon from `tyr-archive/config/catalog.toml`.

## Categories

- **Tier-1** (V1, ship first): clinical accountability + compliance audit data. Highest sensitivity, hardest to reproduce.
- **Tier-2** (V2): per-tenant operational data with PHI/PII implications.
- **Tier-3** (V3): low-sensitivity audit and reproducibility data.
- **Excluded**: data already authoritative elsewhere (git, GitHub issues, HuggingFace) or explicitly off-limits (raw Syn images).

## Tier-1 — V1 ship

### tyr-alerts
- **Owner**: Tyr (Wazuh SIEM)
- **Source**: OpenSearch index pattern `wazuh-alerts-4.x-*` on `wazuh-indexer.wazuh.svc.cluster.local:9200`
- **Sensitivity**: confidential audit (no PHI)
- **Encryption**: Google-managed
- **Skuggi gate**: tier1-text (already shipped, W1)
- **Destination**: `tenants/<tenant_id>/tyr/alerts/<YYYY>/<MM>/<DD>/alerts-<YYYY-MM-DD>.jsonl.zst`
- **Format**: JSONL, one alert per line, zstd lvl 19
- **Schedule**: daily 02:00 (tenant-local)
- **Retention**: 7 yr (HIPAA-equivalent audit retention)
- **Compliance tags**: hipaa, pdpa, oic

### tyr-audit
- **Owner**: Tyr (Wazuh audit channel)
- **Source**: OpenSearch index pattern `wazuh-audit-*`
- **Sensitivity**: confidential audit (access events; may reference user IDs)
- **Encryption**: Google-managed
- **Skuggi gate**: tier1-text
- **Destination**: `tenants/<tenant_id>/tyr/audit/<YYYY>/<MM>/<DD>/audit-<YYYY-MM-DD>.jsonl.zst`
- **Schedule**: daily 02:15
- **Retention**: 7 yr
- **Compliance tags**: hipaa, pdpa, oic

### tyr-fim
- **Owner**: Tyr (file integrity monitoring channel)
- **Source**: OpenSearch index pattern `wazuh-fim-*`
- **Sensitivity**: confidential audit
- **Encryption**: Google-managed
- **Skuggi gate**: tier1-text
- **Destination**: `tenants/<tenant_id>/tyr/fim/<YYYY>/<MM>/<DD>/fim-<YYYY-MM-DD>.jsonl.zst`
- **Schedule**: daily 02:30
- **Retention**: 7 yr

### bifrost-frames
- **Owner**: Bifrost (orchestrator)
- **Source**: `/data/agents/agent_<id>_session_<id>.mv2` on Bifrost pod's PVC
- **Sensitivity**: clinical accountability — frames may reference patient context
- **Encryption**: CMEK (customer KMS)
- **Skuggi gate**: tier1-text + future tier2-NER (when ready)
- **Destination**: `tenants/<tenant_id>/bifrost/frames/<YYYY>/<MM>/<DD>/<session_id>.mv2`
- **Format**: original `.mv2` (memvid-core) — preserves frame-level metadata
- **Schedule**: hourly 00:55 (catches sessions closed within the hour)
- **Retention**: 7 yr (matches encounter retention)
- **Compliance tags**: hipaa, pdpa, clinical-accountability

## Tier-2 — V2

### eir-openemr-db
- **Owner**: Eir (OpenEMR API gateway)
- **Source**: MariaDB `openemr` database in `asgard-medical` namespace (or tenant-specific NS)
- **Sensitivity**: **HIGH** — full clinical record (patient, encounter, observation, payment audit)
- **Encryption**: **CMEK required** (customer KMS)
- **Skuggi gate**: skip (dump is binary, encrypted; PHI must transit but stays opaque to Megawiz)
- **Destination**: `tenants/<tenant_id>/eir/db-dumps/<YYYY>/<MM>/<DD>/openemr-<YYYY-MM-DD>.sql.zst`
- **Format**: `mariadb-dump --single-transaction` → zstd
- **Schedule**: daily 03:00
- **Retention**: 10 yr (medical records law, longest of all)
- **Compliance tags**: hipaa, pdpa, medical-records-law

### mimir-mariadb
- **Owner**: Mimir (RAG)
- **Source**: MariaDB `mimir` schema (documents, chunks, entities, rag_eval_runs, etc.)
- **Sensitivity**: per-tenant — medical tenant has PHI, insurance has PII
- **Encryption**: CMEK
- **Skuggi gate**: skip (binary dump)
- **Destination**: `tenants/<tenant_id>/mimir/mariadb/<YYYY>/<MM>/<DD>/mimir-<YYYY-MM-DD>.sql.zst`
- **Schedule**: weekly Sunday 04:00 (large)
- **Retention**: 7 yr

### mimir-qdrant
- **Owner**: Mimir
- **Source**: Qdrant collections via snapshot API (`POST /collections/<coll>/snapshots`)
- **Sensitivity**: embedding vectors — typically no recoverable PII but treat as PII-adjacent
- **Encryption**: CMEK
- **Skuggi gate**: skip
- **Destination**: `tenants/<tenant_id>/mimir/qdrant/<YYYY>/<MM>/<DD>/<collection>.snapshot`
- **Collections in V2**: `icd10-th`, `primekg-entities`, `pubmed-abstracts`, `clinical-wisdom`, `source_chunks`, `golden_qa`, plus per-tenant insurance/medical collections
- **Schedule**: weekly Sunday 04:30
- **Retention**: 7 yr

### mimir-neo4j
- **Owner**: Mimir (PrimeKG + future guideline lineage per `mimir_guideline_lineage_plan`)
- **Source**: `cypher-shell` dump of PrimeKG subgraph (auth via `neo4j-secret.NEO4J_AUTH` per fixed [backup-shared-kbs.sh](../../../../Mimir/scripts/backup-shared-kbs.sh))
- **Sensitivity**: knowledge graph, not PHI (PrimeKG is public; tenant-specific lineage may reference org)
- **Encryption**: Google-managed (PrimeKG public) / CMEK (lineage)
- **Skuggi gate**: tier1-text
- **Destination**: `tenants/<tenant_id>/mimir/neo4j/<YYYY>/<MM>/<DD>/primekg-dump.cypher.zst` + `manifest.txt`
- **Schedule**: weekly Sunday 05:00
- **Retention**: 7 yr

### syn-redactions
- **Owner**: Syn (OCR + redaction pipeline)
- **Source**: MariaDB `ocr_documents` + `pii_redactions` tables, plus `ocr_layout_eval_*` (asgard_platform only)
- **Sensitivity**: redaction audit — proves compliance of extraction
- **Encryption**: CMEK
- **Skuggi gate**: tier1-text on JSONL rows
- **Destination**: `tenants/<tenant_id>/syn/redactions/<YYYY>/<MM>/<DD>/`
- **Schedule**: daily 02:45
- **Retention**: 7 yr (PDPA processing record)
- **EXCLUDED**: raw images per `syn_data_internal_only` (NEVER cloud-upload). Only redacted/extracted text + audit metadata + hash of source image.

## Tier-3 — V3

### heimdall-calls
- **Owner**: Heimdall (LLM gateway, native on host)
- **Source**: Heimdall structured JSON logs (`logs/heimdall-calls-<date>.jsonl`)
- **Sensitivity**: operational — by default hash-only (prompt/response hashed before logging); raw text optional behind a per-tenant flag
- **Encryption**: Google-managed (hash-only) / CMEK (if raw enabled)
- **Skuggi gate**: tier1-text (catches accidental raw PII)
- **Destination**: `tenants/<tenant_id>/heimdall/calls/<YYYY>/<MM>/<DD>/calls-<YYYY-MM-DD>.jsonl.zst`
- **Schedule**: daily 02:30
- **Retention**: 1 yr (operational, not compliance)

### vardr-traces
- **Owner**: Vardr (observability) — but data lives in OTel traces backend (Tempo if deployed)
- **Source**: Tempo blocks via direct S3-compatible export, NOT through Vardr the dashboard
- **Sensitivity**: agent traces may include patient context references
- **Encryption**: CMEK
- **Destination**: `tenants/<tenant_id>/vardr/traces/<YYYY>/<MM>/<DD>/`
- **Schedule**: native Tempo lifecycle (continuous) → GCS interop endpoint
- **Retention**: 7 yr for medical-tenant traces, 90 days for insurance/operational
- **Note**: Tempo's built-in S3 backend handles this; tyr-archive does not move traces.

### platform-eval-baselines
- **Owner**: Megawiz platform team
- **Source**: `Mimir/docs/04_03_*` scoreboards + `Mimir/eval/*/results/*.jsonl`
- **Sensitivity**: low — Megawiz IP, no customer data
- **Encryption**: Google-managed
- **Destination**: `_platform/eval-baselines/<YYYY-MM-DD>-<bench-name>/`
- **Schedule**: on-demand (manual push after each baseline locks — see `m1_baseline_2026_05_19`, `s1_baseline_2026_05_17`)
- **Retention**: 5 yr (reproducibility)

### platform-code-snapshots
- **Owner**: Megawiz
- **Source**: tar of `~/Developer/` (excluding `target/`, `node_modules/`, `.venv/`, T7 paths)
- **Sensitivity**: Megawiz IP
- **Encryption**: Google-managed (or CMEK if includes customer configs)
- **Destination**: `_platform/code-snapshots/<YYYY-MM-DD>-<tag>/`
- **Schedule**: weekly Sunday 06:00 + on-demand before destructive ops
- **Retention**: 5 yr
- **Replaces**: T7 `asgard-backup-2026-05-10/01-code/repos.tar.gz` style backups

### platform-models
- **Owner**: Megawiz ML team
- **Source**: Custom fine-tune outputs (when Sprint 55+ NER finetune ships per `ner_finetune_plan`)
- **Sensitivity**: Megawiz IP
- **Encryption**: Google-managed
- **Destination**: `_platform/models/<model-name>/<semver>/`
- **Schedule**: on-demand (manual push after training)
- **Retention**: indefinite while model is in use; delete N+2 versions back

## Excluded — never archived

| Source | Why excluded | Alternative |
|---|---|---|
| Syn `data/images/*` (30 real medcert images) | `syn_data_internal_only` — never cloud-upload | Hashes + redacted text in `syn-redactions` |
| HF-derived model weights (Qwen3.5-397B-A17B-4bit 411 GB, bge-m3, typhoon-ocr-3b, etc.) | Re-downloadable from HuggingFace | Record URL + SHA-256 in `model-registry.md` |
| `hf_cache/` (52 GB) | Auto-rebuilds | n/a |
| `Heimdall-Models/Graveyard/` (57 GB) | Deprecated; delete instead | n/a |
| Eir agent variants (`eir-cardio`, `eir-sleep`, etc.) | Per `asgard_agent_registry` — DB rows in `agent_configs`, not files; covered by eir-openemr-db or mimir-mariadb | n/a |
| PrimeKG raw CSV (Harvard public) | Re-downloadable | Reference URL in `Mimir/data/PrimeKG/README.md` |
| Forseti test results, Muninn fix DB, Huginn scan DB | Git/GitHub issues are authoritative | n/a |
| Vardr operational logs (its own logs, not the data it displays) | Disposable | n/a |
| Hermodr (stateless) | No data | n/a |

## Schema for catalog.json (machine-readable)

```json
{
  "$schema": "https://asgard.example/schemas/archive-catalog-v1.json",
  "generated_at": "2026-05-19T23:30:00Z",
  "tenant_id": "asgard_medical",
  "datasets": [
    {
      "id": "tyr-alerts",
      "tier": 1,
      "owner": "tyr",
      "source": {
        "type": "opensearch",
        "host": "wazuh-indexer.wazuh.svc.cluster.local:9200",
        "index_pattern": "wazuh-alerts-4.x-*",
        "query_template": "@timestamp >= '{since}' AND @timestamp < '{until}'"
      },
      "destination": {
        "bucket": "asgard-archive",
        "prefix_template": "tenants/{tenant_id}/tyr/alerts/{yyyy}/{mm}/{dd}/",
        "object_name_template": "alerts-{yyyy}-{mm}-{dd}.jsonl.zst",
        "encryption": "google-managed",
        "compression": "zstd:19"
      },
      "schedule": {
        "cron": "0 2 * * *",
        "timezone": "Asia/Bangkok"
      },
      "retention_days": 2555,
      "skuggi_gate": "tier1-text",
      "compliance_tags": ["hipaa", "pdpa", "oic"],
      "data_classification": "confidential-audit",
      "pii_present": false,
      "phi_present": false
    }
  ]
}
```

The `tyr-archive` daemon reads its TOML config (next to the binary), generates this JSON catalog per tenant at startup, and pushes a copy to `tenants/<tenant_id>/_meta/catalog.json` on every run. Auditors can fetch the catalog without restoring data to know what was archived when.
