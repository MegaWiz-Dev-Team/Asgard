# Asgard Skills Format Specification

> Compatible with [DeerFlow](https://github.com/bytedance/deer-flow) ecosystem

## Directory Structure

```
Asgard/skills/
├── SPEC.md              ← This file
├── public/              ← Built-in skills shipped with Asgard
│   └── <name>/SKILL.md
└── custom/              ← Tenant/user-created skills
    └── <name>/SKILL.md
```

Every skill is one directory, and its name equals the frontmatter `name`. The skills in this repo (generated by `tools/skill-check`):

## SKILL.md Format

Each skill is a **Markdown file** with **YAML frontmatter**:

```yaml
---
name: skill-name              # REQUIRED — unique identifier (kebab-case)
description: >                # REQUIRED — when to trigger this skill
  Natural language description used by the agent router
  to decide when to load this skill.
version: "1.0"                # optional — semver
author: asgard-team           # optional
tags: [tag1, tag2]            # optional — used for relevance matching
tools: [mcp_tool_1, tool_2]   # optional — MCP tools this skill needs
status: active                # optional — active | draft | retired
---

# Skill Name

## Overview
What this skill does and when to use it.

## Instructions
Step-by-step workflow the agent should follow.

## Quality Bar
Expected output quality criteria.
```

### Required Fields

| Field | Type | Description |
|---|---|---|
| `name` | string | Unique skill identifier (kebab-case) |
| `description` | string | Trigger description for progressive loading |

### Optional Fields

| Field | Type | Default | Description |
|---|---|---|---|
| `version` | string | `""` | Semantic version |
| `author` | string | `""` | Skill author |
| `tags` | list | `[]` | Keywords for relevance matching |
| `tools` | list | `[]` | Required MCP tools |
| `status` | string | `active` | `active`, `draft` (written, not ready to load), or `retired` |

Any other key is rejected, so a typo such as `tool:` fails the check instead of being ignored.

## Progressive Loading

> **Status (2026-10-04): not wired.** No runtime reads this directory today. The Python `SkillsLoader` from Sprint 35 was removed with the rest of the Python legacy (Bifrost `7cd664c`, 2026-04-08). The Rust loader is specified in Bifrost [`docs/design/skill-loader-runtime.md`](https://github.com/MegaWiz-Dev-Team/Bifrost/blob/main/docs/design/skill-loader-runtime.md) (draft), which selects skills by embedding the `description`, so write the description as the trigger. The rest of this section describes the intended behaviour.

Skills are **NOT** loaded all at once. The `SkillsLoader` matches the current task description against skill `description` and `tags` fields, and injects only relevant skills into the agent's system prompt as:

```xml
<skills>
<skill name="skill-name">
[markdown content]
</skill>
</skills>
```

This keeps the context window lean and works well with token-sensitive models.

## Creating Custom Skills

1. Create a directory under `skills/custom/your-skill-name/`
2. Add a `SKILL.md` file following the format above
3. Run `skill-check --write` (below) to add it to the index and check it

## Validation

`tools/skill-check` checks this directory against this spec. From the repo root:

```
cargo run --manifest-path tools/skill-check/Cargo.toml -- --root .           # check only
cargo run --manifest-path tools/skill-check/Cargo.toml -- --root . --write   # regenerate blocks, then check
```

It fails on missing or off-schema frontmatter, a name that is not kebab-case or not its directory, an empty description or one over 1024 characters, a `SKILL.md` outside `public/` or `custom/`, a duplicate name, and a stale, unknown, or unterminated generated block. `tools/skill-check/tests/invariants.rs` holds one fixture tree per rule and proves each rule can fail.

Generated blocks are HTML comments that open with `skill-check:begin <generator>` and close with `skill-check:end`. The tool owns their contents, so edit the source, not the block:

- `skill-index` is the table above, built from every skill's frontmatter.
- `k3s-deploy-targets` is the list of `case "$TARGET" in` arms in `scripts/k3s-deploy.sh`.
